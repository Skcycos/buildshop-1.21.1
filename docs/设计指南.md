==================================================
四、商店定位
==================================================

这是一个面向建筑玩家的高频建材采购商店。

核心体验：

- 商品由数据包定义。
- 商品使用卡片网格排列。
- 左侧显示自定义分类。
- 卡片显示真实 Minecraft 物品材质。
- 商品价格按单个物品计算。
- 默认库存无限。
- 支持数据包配置有限库存。
- 支持原版物品和其他 Mod 的物品。
- 支持不同的货币提供者。
- 暂时不实现建筑材料包、组合包或套餐功能。

==================================================
六、真实物品材质
==================================================

禁止使用以下方案：

- Emoji
- 手写 CSS 图标
- 假的颜色方块
- 手动制作一套替代图片
- 只使用物品 ID 文本代替图标

必须优先使用 Minecraft 原生 ItemStack 和 ItemRenderer：

1. 服务端发送商品的物品资源 ID。
2. 如果商品存在组件数据，也一起发送。
3. 客户端根据数据构造真实 ItemStack。
4. 使用 Minecraft 原生 ItemRenderer 或 GuiGraphics 渲染。
5. 将物品图标显示在 AUI 商品卡片中。
6. 支持其他 Mod 注册的物品材质。
7. 支持颜色、变体、组件和特殊物品数据。

如果 AUI 不能直接绘制 ItemStack：

- 在客户端 Java 侧生成真实物品图标缓存。
- 使用动态纹理、Framebuffer 或 AUI 支持的图片资源方式显示。
- 不要退回到手写假图标。
- 如果客户端没有安装对应的物品 Mod，显示“物品材质不可用”的安全占位状态。
- 对材质加载失败记录清晰日志，但不能导致客户端崩溃。

请先检查当前 ApricityUI 版本支持的图片、资源和 DOM API，不要凭空假设 API 名称。

==================================================
七、数据包商品格式
==================================================

建议商品路径：

```text
data/buildingshop/building_shop/products/oak_planks.json
```

商品示例：

```json
{
  "id": "oak_planks",
  "item": "minecraft:oak_planks",
  "components": {},
  "categories": [
    "wood",
    "building"
  ],
  "currency": "server_menu:lc_bank_main",
  "unitPrice": 2,
  "bulkSize": 64,
  "stock": {
    "mode": "infinite"
  },
  "displayName": "橡木板",
  "description": "常用的基础建筑材料",
  "enabled": true,
  "sort": 10
}
```

字段要求：

- `id`：商品稳定 ID。
- `item`：物品资源 ID，支持其他 Mod。
- `components`：可选，用于支持 1.21.1 物品组件或变体。
- `categories`：分类 ID 列表，一个商品可以属于多个分类。
- `currency`：货币提供者 ID。
- `unitPrice`：单个物品价格。
- `bulkSize`：Shift + 左键购买数量。
- `stock.mode`：
  - `infinite`：无限库存。
  - `finite`：有限库存。
- `stock.quantity`：有限库存数量。
- `displayName`：可选的自定义显示名称。
- `description`：商品描述。
- `enabled`：是否启用商品。
- `sort`：商品排序值。

有限库存示例：

```json
{
  "stock": {
    "mode": "finite",
    "quantity": 5000
  }
}
```

商品价格必须按照单个物品计算。

例如：

```text
单价 2
购买 1 个：2
购买 64 个：128
```

价格计算必须使用整数最小单位，禁止使用浮点数造成扣款误差。

==================================================
九、购买快捷键
==================================================

必须支持以下购买模式：

### 左键

购买 1 个商品。

### Shift + 左键

购买一组商品：

- 优先使用商品的 `bulkSize`。
- 没有配置 `bulkSize` 时，使用 ItemStack 最大堆叠数量。
- 例如方块通常购买 64 个。
- 直接放入玩家背包。
- 如果背包无法容纳完整一组，建议整笔购买失败，不扣款。

### Ctrl + 左键

尽可能多购买：

- 根据余额计算最大数量。
- 根据有限库存限制最大数量。
- 根据背包空间限制最大数量。
- 根据服务端单次购买上限限制最大数量。
- 最终数量必须由服务端计算。
- 可以放入多个背包堆叠。

### 右键

打开数量选择窗口：

- 玩家输入购买数量。
- 显示预计总价。
- 显示预计占用背包空间。
- 点击确认后发送购买请求。
- 服务端重新校验所有数据。

不实现以下功能：

- 建筑材料组合包
- 建筑方案包
- 多材料套餐
- 自动购买整套建筑材料

客户端网络包只能发送：

```text
productId
purchaseMode
requestedQuantity
requestId
```

客户端不能发送可信价格、最终数量或最终物品。

==================================================
十、货币系统
==================================================

商店必须支持服务器中的多种经济系统：

- 账户型虚拟经济
- 普通虚拟货币
- 物品货币
- 任务积分
- 其他 Mod 提供的经济系统

不要把商店逻辑绑定到某一个具体经济 Mod。

设计公共接口：

```java
public interface ShopCurrencyProvider {
    String id();

    String displayName();

    long balance(ServerPlayer player);

    boolean canWithdraw(ServerPlayer player, long amount);

    PaymentResult withdraw(
            ServerPlayer player,
            long amount,
            String reason,
            String requestId);

    PaymentResult refund(
            ServerPlayer player,
            long amount,
            String reason,
            String requestId);

    String format(long amount);
}
```

可以根据实际 NeoForge API 调整返回值，但必须保留这些能力：

- 提供者 ID
- 显示名称
- 查询余额
- 检查余额
- 扣款
- 退款
- 金额格式化
- requestId 幂等
- 明确的失败原因

要求：

- 外部 Mod 可以在初始化时注册货币提供者。
- 商品 JSON 通过 `currency` 字段选择提供者。
- 每种货币由自己的 Provider 负责解释金额单位。
- 虚拟货币可以使用整数最小单位。
- 物品货币 Provider 负责移除和返还 ItemStack。
- 不同货币可以拥有不同的显示格式。
- 货币提供者不存在时，商品不能购买。
- 货币提供者扣款失败时，不能发货。
- 发货失败时必须退款。
- requestId 重试不能导致重复扣款。

建议提供：

```java
public final class BuildingShopApi {
    public static void registerCurrencyProvider(
            ShopCurrencyProvider provider);

    public static Optional<ShopCurrencyProvider> currencyProvider(
            String id);

    public static List<ShopProduct> products();

    public static Optional<ShopProduct> product(String id);

    public static PurchaseResult purchase(
            ServerPlayer player,
            String productId,
            PurchaseMode mode,
            int requestedQuantity,
            String requestId);
}
```

所有玩家账户和购买操作必须在服务端主线程执行。

==================================================
十一、服务端购买事务
==================================================

购买流程必须由服务端完成：

1. 检查商品是否存在。
2. 检查商品是否启用。
3. 检查物品 ID 和组件数据是否合法。
4. 根据购买模式计算数量。
5. 检查数量上限。
6. 检查有限库存。
7. 检查背包空间。
8. 获取指定货币 Provider。
9. 检查玩家余额。
10. 扣除货币。
11. 发放 ItemStack。
12. 扣除有限库存。
13. 保存商店数据。
14. 发布购买成功事件。
15. 推送新的余额、库存和商品状态。

任何一步失败：

- 不扣款。
- 不发货。
- 不减少库存。

如果扣款后发货失败：

- 必须退款。
- 必须记录日志。
- 必须向玩家发送清晰的错误消息。

必须防止：

- 重复点击导致重复购买。
- 客户端伪造价格。
- 客户端伪造数量。
- 客户端伪造物品。
- 背包满时扣款但不发货。
- 有限库存出现负数。
- 服务器重启后有限库存丢失。

==================================================
十二、库存系统
==================================================

默认库存模式为无限库存。

同时支持有限库存：

```json
{
  "stock": {
    "mode": "finite",
    "quantity": 1000
  }
}
```

要求：

- 无限库存商品不需要保存剩余数量。
- 有限库存必须保存到 SavedData。
- 有限库存不能出现负数。
- 购买成功后才扣减库存。
- 购买失败不扣减库存。
- 服务器重启后库存保持。
- 数据包重载不能无条件重置运行中的库存。
- 数据包删除商品时，已经存在的库存数据不能导致服务器崩溃。
- UI 必须显示“无限库存”或剩余库存数量。

未来可以扩展：

- 每日补货
- 管理员补货
- 玩家限购
- 定时库存刷新

但本阶段不需要实现这些功能。

十四、网络与安全
==================================================

要求：

- 服务端是唯一价格来源。
- 服务端是唯一库存来源。
- 服务端是唯一物品来源。
- 服务端是唯一货币扣款来源。
- 客户端不能直接修改库存。
- 客户端不能直接创建物品。
- 客户端不能绕过货币 Provider。
- 所有请求必须检查玩家是否在线。
- 所有请求必须在服务端主线程处理。
- 对购买请求进行简单频率限制。
- requestId 必须支持幂等。
- 日志中不能打印敏感信息。
- 非法商品 ID、非法数量、非法模式必须安全拒绝。
